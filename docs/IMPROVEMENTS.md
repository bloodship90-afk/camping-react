# 캠핑장 예약 현황판 보완 결과

기준: 2026-10-25 / 기존 main `ae2efb25e6e2c71a011af19bdb370d2292c39e23`

가족이 확인하고 운영자가 편집하는 사용 방식에 맞춰 13개 영역을 보완했습니다.
로그인·계정·역할 권한 기능은 추가하지 않았습니다. 기본 보기 모드는 실수 방지용이며 편집으로 직접 전환할 수 있습니다.
기존 Firebase 데이터 경로와 키를 유지하며, 운영 데이터 접근·수정이나 운영 배포는 수행하지 않았습니다.

## 13개 영역 처리

| 영역                | 적용 내용                                                                                                                                                           |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. 취소 예약 재등록 | 같은 플랫폼·번호의 취소 이력을 신규 가져오기에서 차단. 신규·취소가 섞인 알림은 신규 제외 후 취소 대상 확인. 복구는 명시적으로 실행                                  |
| 2. 입력 검증        | 등록 사이트, 실제 날짜, 1~365 정수 박수, 이름, 플랫폼, 전화번호 형식 확인. 불완전한 알림은 수정 후 선택                                                             |
| 3. 알림 분석        | 캠핏·땡큐 혼합 인식, 콜론 공백 차이와 일반 사이트 표기 처리, 전화번호 전체 유지. 오류·충돌·반복·과거 제외를 원문과 함께 표시                                        |
| 4. 오래된 미리보기  | 입력 변경 즉시 후보 초기화. 원격 데이터가 달라져도 재분석 필요                                                                                                      |
| 5. 저장 안정성      | 전체 선택 묶음을 한 트랜잭션으로 저장. 연속 클릭 차단, 서버 완료 확인, 재시도 중 동일 키 유지, 변경된 기존 예약 덮어쓰기 차단. 변경 알림을 비교 후 수정 후보로 제공 |
| 6. 취소 대상        | 플랫폼과 번호를 우선 확인. 보조 매칭·여러 후보는 사용자가 한 예약을 선택해야 처리                                                                                   |
| 7. 기존 이상 데이터 | 잘못된 레코드를 화면에서 안전하게 정규화하고 문제 목록으로 안내. 자동 원격 변환 없이 직접 수정. 기존 추가 필드 보존                                                 |
| 8. 날짜·박수        | 현황판·목록·중복 검사에 공통 날짜 계산 사용. 문자열 박수 처리, 자정 기준 주간 계산, 다음 월요일 제외                                                                |
| 9. 통계             | 사이트 점유일을 유일하게 집계해 중복 때문에 점유율이 100%를 넘지 않음. 선택 주에 속한 중복만 경고                                                                   |
| 10. 목록·지난 숙박  | 미래·취소를 과거 숙박 건수에서 제외. 기간 중 숙박/입실 기준 선택. 전체 기간과 전체 필터 초기화 분리                                                                 |
| 11. 연결·실패 표시  | 설정 오류, 최초 로딩, 연결 상태, 마지막 데이터 수신, 저장 대기·성공·실패 표시. 연결·로딩 확인 전 저장 차단                                                          |
| 12. 백업·복구·이력  | 원본 JSON 백업, CSV 내보내기, 취소 예약 개별 복구, 변경 전후 이력. 백업 파일의 전체 자동 복원은 미포함                                                              |
| 13. 유지보수        | 의존성 업데이트, Node 버전 고정, 회귀 테스트, GitHub Actions 검사, 코드 정렬, README 사용·운영 문서 갱신                                                            |

추가로 날짜 직접 이동, 목록에서 상세·수정 열기, 키보드 초점과 Escape 처리, 작은 화면 가로 스크롤 및 입력창, 선택 주 이미지 저장을 보완했습니다.

## 검증 결과

- 자동 회귀 테스트 **58개 통과**: 순수 계산/저장 로직, Firebase SDK mock, 실제 React 화면 이벤트.
- 배포 빌드, 코드 형식 검사, Git 공백 오류 검사 통과.
- npm audit: **알려진 의존성 취약점 0건**. 이는 앱 전체의 보안을 보증하는 결과는 아닙니다.
- 브라우저 체험 모드: 보기→편집, 수동 예약 추가와 현황판 반영, 두 플랫폼 알림 분석·저장, 목록 상세와 취소 반영 확인.
- 390px 모바일 폭에서 현황판과 상세 창 확인.
- 모바일 화면에서 전체 7일/15개 사이트 PNG 생성·다운로드 확인: 2000×1684.
- JSON 다운로드 확인: 예시 6건, 가져온 예약 2건과 생성 이력 포함.
- 취소 복구와 변경 충돌·네트워크 실패·재시도는 자동 테스트로 확인.

## 적용 전에 확인할 점

실제 Firebase 설정이 없는 환경에서 개발했으므로 운영 DB의 권한·검증 규칙과 실제 네트워크 동시 편집은 검증하지 않았습니다.
저장은 `/reservations` 전체의 트랜잭션을 사용하며 해당 경로 읽기/쓰기 및 `createdAt`, `updatedAt`, `_history` 추가 필드가 허용되어야 합니다.
기존 Rules를 자동 변경하지 않습니다.

합치기/배포 전 기존 JSON 백업을 받고 별도 테스트 DB에서 추가→수정→취소→복구, 두 창의 동시 편집, 연결 끊김 후 복구를 확인하세요.
백업은 수동 다운로드이며 자동 일정 백업은 없습니다. 실제 방문 여부를 별도 기록하지 않으므로 “지난 숙박”은 날짜로 계산한 예약 건수입니다.
데이터와 이력이 커지면 전체 경로 트랜잭션 및 이력 보관 규모를 재검토해야 합니다.

설치·설정·사용법은 README에 정리했습니다. 기존 로그인 없는 사용 방식을 유지합니다.
